# K6 Performance Test Framework

A small k6 load-testing framework in JavaScript: scenario tests for smoke,
load, stress, soak, and breakpoint runs, with HTML reports.

## What is in this repo

```
performance-test/
├── package.json          # npm scripts for each scenario
├── src/
│   ├── config/
│   │   ├── base_test.js      # BaseTest: send requests, validate status, delay
│   │   └── test_options.js   # Stage and threshold configs per scenario
│   ├── endpoints/
│   │   └── <source>/
│   │       └── sample_endpoint.js  # Example endpoint set (see below)
│   ├── tests/
│   │   ├── smoke_test.js
│   │   ├── load_test.js
│   │   ├── stress_test.js
│   │   ├── soak_test.js
│   │   ├── breakpoint_test.js
│   │   └── minimal_test.js
│   └── utils/
│       ├── env.js
│       ├── reportHandler.js  # Writes the HTML report
│       └── utils.js
└── reports/              # Sample HTML reports generated by past runs
```

## Running a scenario

k6 must be installed and available on your `PATH`.

```bash
npm run smoke       # k6 run src/tests/smoke_test.js
npm run load        # k6 run src/tests/load_test.js
npm run stress      # k6 run src/tests/stress_test.js
npm run soak        # k6 run src/tests/soak_test.js
npm run breakpoint  # k6 run src/tests/breakpoint_test.js
```

## Response-time thresholds (p95)

Each scenario test sets its own `http_req_duration` threshold, overriding
the defaults in `src/config/test_options.js`:

| Scenario   | p(95) threshold |
| ---------- | --------------- |
| Smoke      | < 500 ms        |
| Load       | < 500 ms        |
| Soak       | < 500 ms        |
| Stress     | < 1000 ms       |
| Breakpoint | < 400 ms        |

The tests also track two custom metrics: request count (`tps`) and
`error_rate` (share of non-200 responses).

## Endpoints

The scenario tests load their endpoints from
`src/endpoints/<source>/sample_endpoint.js`, selected with the
`ENDPOINT_SOURCE` environment variable (for example,
`k6 run -e ENDPOINT_SOURCE=<source> src/tests/smoke_test.js`).
Only a sample endpoint set is shipped with this repo; it points at a
public placeholder API by default (`https://reqres.in`) and can be
overridden with `API_BASE_URL`. Point it at your own test target before
running against a real system. Note the code's default source name has
no matching folder, so set `ENDPOINT_SOURCE` to the name of the
endpoint folder shipped under `src/endpoints/`.

## Reports

Each test's `handleSummary` calls `handleReport` in
`src/utils/reportHandler.js`, which renders an HTML report with
[k6-reporter](https://github.com/benc-uk/k6-reporter) into
`reports/<name>.html`. A few sample reports are committed under
`reports/` as examples of the output format.

## Notes

- This is a starter/sample framework, not a record of production load
  tests. No adoption, coverage, or production-use claims are made here.
- `minimal_test.js` still imports from a `test_config` layout that is
  not present in this repo, so it may need updating before it runs.
- The committed sample reports are example outputs; regenerate them by
  running a scenario.
